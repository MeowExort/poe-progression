# PoE Progression

Планировщик и трекер SSF-прогрессии для Path of Exile с оверлеем поверх игры.
Десктоп-приложение на Electron: читает лог игры `Client.txt` и показывает состояние в окне и в оверлее.

## Запуск

Нужен Node.js 22+.

```bash
npm install
```

```bash
npm run dev
```

## Установка и обновления

Готовый установщик лежит на странице [релизов](https://github.com/MeowExort/poe-progression/releases):
скачай `PoE-Progression-Setup-<версия>.exe` и запусти. Установщик спросит папку (по умолчанию —
профиль пользователя) и ставит приложение только для текущего пользователя: права администратора не нужны,
поэтому папку стоит выбирать такую, куда можно писать без них. Файл не подписан, поэтому Windows при первом
запуске покажет предупреждение SmartScreen: «Подробнее» → «Выполнить в любом случае».

Установленное приложение само проверяет новые версии — при запуске и каждые несколько часов — и скачивает
их в фоне. Когда обновление готово, в окне появляется плашка со списком изменений и кнопкой
«Обновить и перезапустить»; если нажать «Позже», оно установится при следующем закрытии приложения.
Во время забега в Sanctum плашка не показывается. После обновления приложение один раз показывает,
что изменилось. Проверить вручную можно во вкладке «Настройки».

Настройки, история забегов и сохранённый доступ при обновлении не трогаются: они лежат отдельно,
в `%APPDATA%\poe-progression`.

## Сборка установщика самому

```bash
npm run dist
```

В папке `release` появится `PoE-Progression-Setup-<версия>.exe`, рядом — папка `win-unpacked` с тем же
приложением в распакованном виде.

## Выпуск новой версии

1. Дописать в начало `CHANGELOG.md` раздел `## <версия>` — именно он показывается игроку в плашке обновления.
2. Поднять `version` в `package.json` до той же версии и отправить в репозиторий.

Сборку и публикацию делает GitHub Actions (`.github/workflows/release.yml`): релиз выходит только когда
в отправленных изменениях поменялась версия. Без раздела в `CHANGELOG.md` релиз не соберётся.

## Настройка

- Путь к `Client.txt` определяется автоматически (Steam-библиотеки на всех дисках); если не нашёлся — вкладка «Настройки».
- Игра должна быть в режиме **Windowed Fullscreen**: поверх эксклюзивного полноэкранного режима оверлей не рисуется.

## План

Во вкладке «План»: опросник → выбор стартового билда (или сразу импорт своего) → маршрут актов.
После импорта кода Path of Building в маршруте появляются шаги с гемами — у какого квеста взять
наградой и у кого купить именно твоему классу, — а рядом вкладки с гемами, деревьями и предметами билда.
Во вкладке «Предметы» у каждого уника перечислены все способы его добыть — источник дропа, карты
предсказаний, Orb of Chance на базу, выращивание на Genesis Tree с нужными пассивками. У редких вещей
разобран каждый мод: префикс это или суффикс, какой тир, какой уровень предмета нужен и чем его получить —
случайным роллом, фоссилом, крафтом Harvest, эссенцией или станком, с оценкой шанса за попытку по весам
модов. Способ отмечается галочкой и попадает в «Мой план по предметам». Сравнить способы по цене
приложение не умеет — для этого есть Craft of Exile.

### Проверка гемов

Вместе с деревом приложение читает с сайта вещи персонажа и сверяет вставленные гемы с билдом: какого
гема нет (и у кого его взять), какой лежит в инвентаре, какой саппорт стоит отдельно от своего скилла.
Проблемы видны в боковой панели оверлея, полная картина — во вкладке «Гемы». Гем считается обязательным,
когда маршрут прошёл шаг, где он берётся; связи требуются для скилла и первых саппортов — трёх гемов до
25 уровня, четырёх дальше.

Там же, во вкладке «Предметы», надетые вещи сверяются с набором предметов билда: уник — по названию,
редкая вещь — по модам (есть ли такой же мод и не ниже ли он). У гемов рядом с уровнем на персонаже
показан уровень из билда.

### Дерево, лабы и поиск у торговца

С импортированным билдом вкладка «Дерево» показывает, какие пассивные очки брать дальше, а боковая панель
оверлея — ближайшие шесть. Что уже взято, приложение читает с pathofexile.com тем же доступом, что настроен
во вкладке Sanctum. Сайт узнаёт об изменениях только при смене зоны, поэтому после левел-апа или
города дерево перечитывается на следующей смене зоны; есть и кнопка «Обновить с сайта». Порядок очков
приложение выбирает само (к ближайшему нотаблу, кистоуну или мастери из дерева билда): Path of Building его
не хранит. Если в билде несколько деревьев по стадиям, они проходятся от меньшего к большему.

У шагов «Пройди The Labyrinth» указано, какие очки возвышения брать. Блок «Поиск у торговца» над маршрутом
даёт строки для поля поиска в окне торговца: связки в цветах гемов билда и скорость передвижения.

## Лут-фильтр

Вкладка «Фильтр» пишет файл `PoE Progression.filter` в `Документы\My Games\Path of Exile` и обновляет его,
когда меняется билд. В игре он выбирается один раз (Options → Game → Item Filter), после обновления файла
достаточно команды `/itemfilter PoE Progression` в чате.

Фильтр один на всю игру: стадии — акты 1–5, акты 6–10, ранние, средние и красные карты, эндгейм —
заданы уровнем зоны и переключаются сами. Скрываются только белые, синие и жёлтые вещи и фласки; всё
остальное, включая то, о чём фильтр не знает, показывается. Что видно и что скрыто на каждой стадии,
написано во вкладке.

## Sanctum

Вкладка «Sanctum» сама распознаёт забеги по логу игры: считает время каждой комнаты, этажа и забега,
отличает пройденные от проваленных и ведёт статистику за сессию и за всё время.

- **Лут** считается по снимкам инвентаря персонажа с сайта Path of Exile после смены зоны. Сайт показывает
  инвентарь только владельцу аккаунта, поэтому нужна cookie сессии (`POESESSID`): она хранится
  зашифрованной средствами операционной системы и отправляется только на pathofexile.com.
- **Цены** берутся с poe.ninja — по данным внутриигровой биржи валюты.
- **Реликвии** оцениваются автоматически поиском похожих лотов на официальном трейде: по тем же модам,
  а если таких мало — по самому дорогому моду. Оценка грубая: это цены выставленных лотов.
  Моды, которые ценятся всегда, перечислены в `data/valuable-relic-mods.json`: они оцениваются даже по одному лоту.
- **Отслеживаемая валюта** настраивается: список предметов, которые показываются на полоске и в статистике.
- **Полоска** появляется поверх игры на время забега: полученная валюта, 32 комнаты с временем каждой,
  время этажей, забега и сессии, число заходов. Она пропускает клики мыши в игру.

## Оверлей

Хоткей (по умолчанию `Shift+F`) показывает и прячет то, что сейчас уместно: вне Sanctum — боковую панель
с планом, во время забега — полоску. Боковую панель можно отключить совсем. Место и размер каждой
раскладки меняются в «Настройки → Оверлей»: в режиме настройки оверлей перетаскивается и растягивается мышью.

## Разработка

```bash
npm test
```

```bash
npm run typecheck
```

Структура:

- `data` — база знаний: карточки билдов (`builds.json`), способы добычи с цитатами из патчноутов (`methods.json`)
  и данные сторонних проектов в `vendor` (у каждого свой `SOURCE.md` с происхождением и лицензией):
  маршрут актов из exile-leveling (MIT), уники и базы из Path of Building (MIT), карты с PoEDB (CC BY-NC-SA 3.0),
  моды реликвий из Awakened PoE Trade (MIT).
- `scripts` — скрипты, которыми данные в `data/vendor` обновляются после патча.
- `src/core` — логика без привязки к Electron: разбор маршрута, отслеживание позиции, подбор билдов, импорт Path of Building.
- `src/main` — процесс Electron: окна, оверлей, чтение и разбор лога, состояние сессии и плана.
- `src/preload` — мост между окнами и главным процессом.
- `src/renderer` — интерфейс на React (главное окно и оверлей).
- `src/shared` — общие типы.
- `test` — тесты.

Данные приложения (настройки, план, история событий, зашифрованная cookie и кэш цен) лежат в `%APPDATA%\poe-progression`.
